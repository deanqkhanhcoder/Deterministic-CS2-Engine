## 2. Concurrency & Deadlock Elimination Proof

### Thread Model Isolation
The system operates on three primary thread archetypes:
1. **Windows Hook Thread (LowLevelKeyboardProc):** Executes asynchronously.
2. **Timer Thread (`s_spinlock`):** Operates at Realtime priority on a pinned P-Core.
3. **Main UI Thread:** ImGui event loop.

### Lock Graph & Acquisition Order
We enforce a strict directed acyclic graph (DAG) for lock acquisition:
```
s_stateMutex (Engine State) -> s_spinlock (Timer Dispatcher)
```
- **Rule 1:** `s_stateMutex` may invoke `ScheduleTimerUs`, acquiring `s_spinlock`.
- **Rule 2:** `s_spinlock` *never* attempts to acquire `s_stateMutex`.

**Mathematical Proof of Liveness:** Since there is no cycle in the lock graph, a circular wait is strictly impossible. **Deadlocks are formally eliminated.**

### SendInput Isolation (OS Re-entrancy Proof)
Windows `SendInput` is notoriously prone to deadlocks if invoked while holding a lock that a low-level hook might need (Hook Re-entrancy).
To solve this, V26 utilizes `InjectionBatch`.
- State mutation is calculated under `s_stateMutex` and cached into the `InjectionBatch`.
- The mutex is **released**.
- `InjectionBatch::flush()` invokes `SendInput` linearly, safely returning to OS ring-0 without holding any engine locks.
